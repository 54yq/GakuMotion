# 摄影多人舞台 v1

多人舞台使用摄影模式已经创建的最多三名演员。功能默认关闭；槽位观察就绪不代表动作、衣发或最终画面已经通过实机验收。

## 使用方式

在“动作 → 多人舞台（最多3人）”中开启摄影槽位验证探针。探针仅在已确认的 Photography owner 中读取官方槽位、容量、演员/骨架身份、父变换、位姿与回调记录；输出最多120帧，后续只保留身份门禁。更衣室、其他场景、未知 getter 签名和没有真实 Unity 帧号时不能启用多人注入。

将当前演员绑定到逻辑槽位，选择各自动作和是否参与，设置世界坐标 XYZ 米制偏移与绕世界 Y 轴的朝向。主槽提供唯一音乐和 MMD 镜头；镜头页的跟随模式使用另选的跟随槽。主槽和跟随槽必须参与演出，同一演员不能占两个槽位。

播放期间先暂停再配置。应用前预检全部动作、主镜头和演员身份；失败保留原组合及暂停位置。成功应用从0秒预览，不自动播放。复制主槽动作可快速设置齐舞；停止恢复所有仍有效演员的官方动画、表情与站位。

停用多人舞台后恢复单人入口。没有自动建角、克隆、人数扩展、动作混合、编队关键帧或跨场景连续演出。

## 时间、站位与所有权

主播放器是唯一演出时间和音频所有者，副槽只能按该时间采样；同一个 Unity 帧至多推进一次，与演员回调顺序和是否参与无关。各动作保持 `S=max(0,(P-offset_seconds)*speed)`。整场时长包含各参与演员的身体/表情及主槽音乐/镜头；短轨保持末帧。循环作用于整场，不执行播放列表自动下一首；非循环到尾停止整场。

站位在身体与辅助骨完成之后、物理发布和相机读取之前应用一次。朝向旋转整个受控根子树和根轨迹，补偿真实父级世界旋转，子骨局部旋转保持原有语义；不修改官方 actor/layout Transform。零朝向保留原播放路径，反复播放或暂停定位不累计变换。MMD 镜头使用主槽相同的逻辑平移与朝向，跟随读取目标演员实际骨骼。

各槽独立持有绑定、角色表情身份、根高度校准、动作覆盖、原生 talk/Animator 恢复记录和物理状态。演员离场、地址复用、骨架/布局或 owner 变化使整场停止，不猜选其他演员；销毁对象只丢弃缓存，恢复只针对仍有效的身份。截图/分享保护统一暂停并恢复所有槽，不绕过既有保护。

## 组合预设

预设位于活动配置根的 `ensembles/<名称>.json`，版本为1，保存三逻辑槽的参与标志、曲库 key、演员提示、XYZ、朝向，以及主槽和跟随槽。演员指针和 token 不写入文件，载入只更新编辑草稿；重新绑定当前摄影演员并应用后才替换演出。保存采用临时文件与原子替换，失败不覆盖旧预设。

预设引用既有曲库，不复制动作，不重写曲目 `info.json` 或 `playlist.json`。主副槽继续使用各曲目自己的文件时序参数。

## 物理与外部接口

配套 GakuBurstBridge v3 为三演员分配独立 context；实际 job 根据 hair/arm 双指纹唯一路由，context 代次、Quartz/Swing 配对、故障及清理均隔离。工作线程不访问 Unity 元数据。实际原生消费仍有既有的异步/一帧滞后边界，不承诺零延迟或确定性物理。

每槽显示实际后端与原因。伴生库未就绪或单槽故障时该槽使用独立 fallback；旧 v2 库仅固定主槽可用原生物理，其余槽明确显示兼容降级。Publish 被接受不能作为已消费或视觉通过的证据。BeforeQuartz 默认关闭。

现有 Burst trace 导出增加 `actor_contexts`，逐 context 记录 token、generation、hair/arm 双指纹、实际消费源帧、匹配次数和写入数。尚未发布上下文时没有该演员的 job 指纹证据；摄影槽位只读就绪与原生物理实际消费需要分别验收。

Loader ABI 与 Control v0 的结构大小不变。多人激活时，Play/Pause/Stop/Seek/Speed 控制整场，Camera/Scene 仍是全局设置；没有演员参数的 Load/Offset 返回 Unsupported，能力位同步关闭。v0 的曲目/空间状态描述主槽，不提供多人编辑协议。Director、Clock 原型与 Python Timeline 没有在此版本新增连接。

## 验证边界与交付

离线回归验证调度、身份隔离、站位层级数学、预设事务、GUI交互及桥上下文路由；不能替代三演员实际 stream 消费和最终画面验收。实机需依次覆盖1→2→3人、齐舞→独立动作、不同身高/服装、暂停定位/循环、换装/离场、截图恢复和完整退出，并分别录制全身及衣发特写、比较性能。

GakuBurstBridge 是可选伴生组件，与 GakuMotion 插件位于同一个插件目录。可用 `tools/package_ensemble_candidate.ps1` 在构建目录中整理本地候选产物。
