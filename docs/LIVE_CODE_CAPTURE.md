# Live 进程内只读代码采集

本入口在首次成功解析角色动画播放器时自动执行，无需重复记录计数或载入 MMD。普通 Live 播放即可解析目标；暂停前后观测到的调用者地址会在后续角色图采样时补充。若没有发生结束回调，则不会产生真实的结束调用者记录，不能把方法体存在当成已观察到调用链。

输出位于诊断根目录的 `live_code_<pid>/`：

- `methods.tsv`：模块基址、方法地址、Windows unwind 范围、IL2CPP 参数及返回类型、字段偏移、实际序列/控制器类型、文件名和读取状态。
- `code_<n>.bin`：对应内存范围的原始字节。分析时按 TSV 中的 begin 地址加载；不是可直接运行的 DLL。

目标包括 LivePresenter、LiveScenePresenter、LivePlayerPresenter、Live3DPresenter、实际角色播放器、MotionDefinePlayer、AnimationPlayerBase、CampusActorAnimation，以及它们的嵌套异步状态机。实际 `_liveSequence` 和 `_controller` 的类也会采集。

采集在本插件调度挂钩安装前开始。其它插件仍可能已修改方法前缀；这些字节是现场观测，不保证是游戏原始指令。没有 unwind 信息时只保存入口的 128 字节，并标注 prefix_only_no_unwind；长函数截断到 32 KiB 并明确标注。它不是全进程内存转储，也不保证收齐所有外部被调用函数。

边界：最多 64 个类、每类 256 个方法和 256 个字段、2048 个代码地址、8192 个去重记录、代码载荷总量 16 MiB。代码页逐页检查，拒绝不可执行、未提交、PAGE_GUARD 和 PAGE_NOACCESS 页面；访问异常会被包含并记录。不会调用采集到的方法，不会改变页面权限，不会修改角色、播放时间或 Swing 状态。

验证：Runtime 构建；合成的可读执行页、不可执行页、跨越不可访问页、保护页保持测试；现有 Contracts 和 GUI 回归。真实游戏中能否读到受保护方法必须在安装后确认，不由离线测试推断。

安装后一次采集：正常进入 Live，连续播放约 10 秒，暂停数秒再恢复；可以自然播放到结尾以补充结束调用者。游戏可保持运行交由分析，无需另点计数记录按钮。面板的 Swing 检查点显示代码文件数及读取/写入失败数。
