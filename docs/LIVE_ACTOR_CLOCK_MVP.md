# Live 接管与角色图：当前状态

## 运行方式

Live 接管暂停舞台。启用原生物理并发布 Motion 身体姿态后，插件沿已验证属于当前角色的图输出，查找有可读结束时间的 `MotionClipPlayable` 和 `AnimationClipPlayable`。将这些片段的本地时间设为片段结束后一个 60 Hz 帧间隔，并以保持模式把播放速度设为零。角色图照常运行，原生 Swing 继续接收 Motion 姿态。角色图的输出、舞台时间、BeforeQuartz 设置均不参与该时间调整。

角色图可以包含尚无片段来源的输出。扫描跳过空连接，并保留输出快照来检测接管中新增的连接。片段保持在最后的采样状态。若角色图无法提供有限片段时长，或运行过程中有其他驱动重新写入片段时间，则记录原因并在能够安全恢复时继续原生物理兼容模式。结束接管时恢复原片段时间、速度、保持模式和完成标志，并按原有流程恢复角色图和 Live 暂停节点。场景归属变化时不写旧图。通过 `LiveActorClipEnd` 和 `ActorClockPhysics` 分别核对片段是否停在结尾和原生求解是否持续。

普通 Live 的“角色图运行 3 秒”是独立的诊断实验，结束后恢复图和暂停节点。它保留局部图回绕以便在 Live 结尾附近做短时测试，与 MMD 接管连续推进的路径不同。

## 旧版实测证据与限制

2026-11-14，安装版 e56ac1b：用户在 146.349/147.500 秒附近接管，观察无明显问题。日志中角色图根时间从 8.322 增至 85.529 秒，约 77 秒内舞台时间保持不变，图回绕为零；Swing、匹配的原生执行及求解增量均为 8835，54 个骨骼写入，期间没有观察到失败或匹配跳过。图设置和暂停节点的恢复检查通过。

此记录证明接管时长超过原 Live 剩余约 1.15 秒，不能证明角色图根时间超过 Live 总长后仍能运行，也不能单凭停止记录证明退出接管后音乐、镜头和交互都恢复。不同 Live、角色、服装、长时间运行及多角色均需分别验证。原生注入不可用时仍可能回退内建物理，以运行时状态为准。

## 保留的诊断与历史路径

- Swing 实时监控的进程范围入口计数不等于当前角色注入；应结合目标身份、匹配、写入、原生执行和求解记录判断。固定报告最多 64 个样本，不是实时累计。
- 角色图首次识别时仍会自动采集运行时代码；这是历史诊断功能，不应误称为正常播放必需。当前保留，供进一步调查使用。
- “结束前自动循环 Live”使用结束前 Seek 回开头；时间余量过小或卡顿时仍可能错过。结束回调重播路径因黑屏问题保持禁用，不会拦截结束回调。
- 旧的 Swing 全量物理快照及字节级恢复未接入；不要将 Unity 角色图时钟恢复当成物理快照恢复。
- F8 辅助骨切换和手腕诊断由用户要求保留，与角色图时钟是不同功能。

历史设计和早期验证记录保存在 Git 提交历史及其他 research 文档中；本文件描述当前版本。
