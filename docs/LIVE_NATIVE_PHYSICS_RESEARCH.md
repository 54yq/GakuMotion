# Live 接管与原生物理：离线研究

## 2026-11-14：黑屏回归后的实际交付边界

用户需要的最终效果有两项：在 Live 的实际结束边界正常接回开头；舞台定格后继续更新角色与原生 Swing，并能退出恢复。这两项目前均未完成游戏内实现，不能把只读面板、合成契约测试或挂钩安装成功算作功能完成。

### 已经确认的问题与修复

- 最近一次结束回调的观测时间为 147.107788 秒，总时长 147.5 秒。回调比显示时长提前约 0.392 秒，解释了按总时长提前 0.1 秒检测为什么来不及；这是一次观测，不是所有 Live 的固定偏差。
- 原实现从 `OnEndLiveSequence` 内调用 Seek 到 0，观察开头时间和播放标志后吞掉原回调。用户随后报告黑屏且不能交互。日志中的 `restarted=1` 只证明了这两个读数，不能证明结束序列、淡入淡出或交互已恢复。具体哪个收尾状态造成黑屏仍未获证实。
- 提交 `6472dec` 关闭此结束拦截和界面启用入口，原结束回调始终转发，避免继续触发已知回归。该修复本身不提供循环。
- 提交 `b00dabc` 增加只读 Swing 检查点面板和历史报告加载入口。历史地址不能用于当前场景回写；“角色独立更新”仍保持不可用。

### 已取得的数据不等于完整恢复能力

同一份有角色身份匹配的报告中，四类 NativeList 各有 64 次有效头部采样：动态骨 258×956 字节、静态骨 42×136 字节、胸部骨 1×440 字节、骨链 35×140 字节；没有观察到容器变化。有效载荷共 257700 字节，但这些记录只读取头部，并没有保存载荷。

有 63 次匹配求值与 Swing 的重叠样本在求值返回前结束。这支持继续研究该求值入口，但不是所有任务已完成的同步保证。还缺少角色图全部输出的归属确认、真实任务屏障，以及覆盖时钟、原生容器和其它可变状态的恢复适配器。现有 `Session::Start` 的前置条件没有绕过。

### 后续实现需要解决的具体调用路径

- `Campus.Live.LivePresenter` 包含 `_liveSequence`、`CreateLiveSequence`、`BeginLiveLoop`、`InitializeLiveLoopAsync` 和 `ReplayLiveSequenceAsync`。应确认真实序列类型和完整重播链，覆盖结束、音频及淡入淡出，不能再用单次 Seek 代替重播完成。
- `Campus.Live.LivePlayerPresenter.get_ThreeDLive` 对应的类型线索是 `Campus.Live.Live3DPresenter`，而不是名为 `ThreeDLive` 的类。后者包含 `_controller`、`_actors`、`set_TimelineTime`、`Pause`、`Resume`、`ApplyGameTimeUpdate`。这些名称是静态元数据证据，尚未证明哪个入口能只更新角色而冻结舞台。
- `PlayableGraph.SynchronizeEvaluation` 的存在不证明它是等待本角色任务完成的屏障，不可仅凭名称调用。
- 本机磁盘上的 GameAssembly 主要代码区并非完整可直接反汇编的运行时代码；静态元数据可以读到成员名，却没有提供上述方法体。当前离线模块指针扫描未解析出有效方法映射，不能据此猜测私有布局或建立写入适配器。

下一轮采集若确有必要，应只补齐上述实际方法体、序列类型及同步路径，不再重复收集已确认的 Swing 列表长度和求值计数。只有真实游戏适配器接通、恢复逻辑通过离线故障测试后，才可以将功能版本交给用户进行一次合并验收。

## 已观察到的事实

- 2026-11-14 的只读调用记录中，Live 接管前曾记录到与 Swing 入口特征匹配的调用；最近一次记录 368 次，报告的时间步长范围为 0。该调用来自进程范围，尚未证明属于当前角色，也不能证明该阶段物理实际推进。
- 开启接管并播放 MMD 时，桥接器报告挂钩就绪；连续采样中 `swing_calls=0`、`identity_skips=0`、`expired_skips=0`、`native_passes=0`，实际后端回退到内建物理。零匹配失败并不等于角色身份匹配已获验证。
- 角色 Animator 的 `playableGraph` 在接管前后均报告无效；它不能作为另一个独立角色动画图的状态证据。
- 早期探针找到了角色动画组件和 `_animationPlayer`，但由于基类的程序集查找失败，未读取到播放器的图；后续版本改为沿实际类的继承关系定位。
- 后续 Live 诊断已成功找到该播放器及有效图；接管前后均曾报告 `IsPlaying=false`，因此不能仅凭该值判断游戏是否在手动求值。
- 2026-11-14 的后续实机日志在正常 Live、暂停与接管阶段均报告角色图有效且 `update_mode=3`（手动模式），接管播放时 Swing 桥接调用仍为 0。手动模式说明游戏需要显式求值，但不证明当前图的求值会产生目标角色 Swing，亦不能推断暂停前具体调用者。
- 用户报告 Live 进度拖动实测正常；正常 Live 走到末尾会自动退出。当前接管依赖暂停 Live，MMD 使用独立时钟，并已有单曲循环选项。仅上述事实不能证明超过 Live 时长的完整视觉与退出恢复已被验证。
- 拍摄现场和 Live 接管复用相同的 MMD 播放入口及 Swing 桥接路径。查看当前可用日志时，拍摄现场有选择原生后回退内建的记录，没有发现 `live=0 requested=2 actual=2` 的成功记录。日志范围有限，不能由此断定拍摄现场一定不可用。
- 为比较现场的实际调度，新版只读探针在确认拍摄现场、目标角色和动作播放后记录该角色图；它不创建对象或手动推进图。该数据仍需同一角色、服装和动作的现场及 Live 实机对照，不能把人物可见运动等同于 Swing 正在运行。

## 元数据与代码线索

离线元数据包含 `VL.Animation.AnimationPlayerBase` 的 `_graph`、`GetPlayableGraph()` 和 `CreatePlayableGraph()`；`CampusActorAnimationBuilder` 有 `Build(animator, graph, actorAnimationRig)`、`BuildRigPlayable(graph)`；`CampusActorAnimationJob` 列有 `ProcessAnimation` 和 `ProcessSwingSkeleton`。这些成员支持“角色动画任务可能由单独图调度”的推断，但名称不能证明实际实例、连接关系、调用顺序或线程行为。

`PlayableGraph` 暴露 `IsValid`、`IsPlaying`、`GetTimeUpdateMode`、`SetTimeUpdateMode` 和 `Evaluate(deltaTime)`。存在这些接口不等于当前图能安全手动推进，也不表明推进后只会计算物理。手动求值可能同时推进原 Live 姿态、播放事件、镜头或其他节点，或与 Unity 的自动调度重复执行。

当前桥接器在游戏 Swing 任务的真实回调中验证角色身份、检查数据代际和有效期，才把 MMD 姿态写入当次 `AnimationStream`，随后调用游戏原解算。它不缓存或伪造 stream，也不主动调用原生 Swing。现有 `ClearForCapture`、角色姿态和 Live 播放恢复机制没有记录原生 Swing 的内部动态缓存，因此不能把图状态恢复视为完整的物理状态恢复。

补充离线检查：Swing 动态骨元数据包含 `childSpeed`、`cachedTransform`、`wind` 等字段，骨骼列表和 `_time` 位于 Swing 任务状态中。字段名称不证明能复制原生容器、恢复所有权或安全回写。桥接器的 `Clear` 只使当前数据失效并推进代际，未提供等待正在执行的原生任务退出的同步屏障，因此也不能用 Clear 成功证明物理状态可以安全快照。`ResetDynamicBone` 的存在同样不能证明等价于恢复接管前状态。

## 候选方案及前置条件

1. 在游戏主线程只读解析当前角色组件、实际播放器、图及身份；确认图有效、取值来自该角色，记录图的播放状态、更新时间模式及 Live 时间。查询失败、场景或所有者变化则不可操作。
2. 明确图的输出与调度归属，确认它没有驱动舞台时间线或共享给其他角色。在暂停前后比较其状态与 Swing 调用；当前离线元数据无法完成这一步。
3. 仅在能避免 Unity 自动求值和手动求值同时发生、并且能恢复原更新时间模式与播放状态时，才考虑默认关闭的手动推进实验。每个物理帧至多一次，时间步长有上限；先发布当前 MMD 姿态，再在原生回调中验证 actor、stream、代际及消耗帧。原 Live 时间、音频和镜头不能推进。
4. 实验中同时记录图状态、Live 时间、Swing 调用、身份失败、实际注入、身体覆盖和物理效果，验证正常播放、暂停/续播、切曲、切场景和关闭接管。异常时停止实验并回退；不能用挂钩就绪当作物理成功。
5. 退出时停止新求值、清除桥接输入并等待并发任务结束，然后恢复图状态、角色和 Live 原状态。原生 Swing 内部的模拟状态是否有可验证的快照/恢复路径仍未知；`ResetDynamicBone` 等方法只证明名称存在，不证明效果、线程安全或可逆，不能直接调用作为恢复保证。

目前没有足够证据安全实现或声称此实验有效。下一次实机版本应把读取图、状态变化、调度与恢复验证合并；在无法满足上述条件前保持原有回退机制。
